- Classic/legacy animation references can be off by one relative to this viewer's catalog IDs. Example: classic `GEN_ANIM_FOUDRE = 39` maps through `file3D` to legacy `anim_index=49`, which loads `anim0050.ldc`; in this viewer that is `ANIM.HQR:49`, not `ANIM.HQR:50`. The visible lightning bolt is also emitted by the animation action `F_THROW_FOUDRE`, not stored in the Twinsen body animation mesh itself.
- LBA2 animation interpolation is not direct `elapsed / duration` truncation. Classic `ObjectSetInterDep` first computes a rounded 16.16 interpolator with `((deltaSteps << 16) + ((nbSteps + 1) >> 1)) / nbSteps`, and `ObjectSetInterFrame` applies that interpolator with signed right shifts. Direct division can be off by one on real ANIM frames.
- Root-level `viewer.py` and `lba_hqr.py` are currently documented compatibility wrappers even though project policy says not to preserve compatibility bridges by default. Treat them as an explicit current-state exception, not a pattern to extend.
- Animation sequence playback needs a separate loop segment. The first frame of that loop segment must interpolate from the last keyframe, not from itself or from the intro frame, or looping idles such as `ANIM.HQR:66` snap at the wrap boundary.
- Playback frames are not uniquely identified by `(frame, elapsed_ms)` once a loop segment exists. Frontend code should carry `sequence_index`/`segment` and loop-cycle count through scrubbing, pause/resume, and repeat playback; otherwise repeat-off can play the synthetic loop segment and translating world-motion animations can snap their root offset on repeat.
- Animation compatibility is not just bone count when File3D metadata exists. `animation_metadata.compatible_body_ids` is an allow-list for `BODY.HQR` models; otherwise same-bone unrelated actors, such as Twinsen wizard tunic and the emperor, can appear to share valid animations.
- `ANIM3DS.HQR` uses classic zero-based HQR indexing like `BODY.HQR`, not the regular one-based archive path used by `ANIM.HQR`. Entry 127 is the `T_ANIM_3DS` frame-range table loaded by the original runtime; treating ANIM3DS as one-based hides frame 0 and shifts the table to the wrong catalog identity.
