- Classic/legacy animation references can be off by one relative to this viewer's catalog IDs. Example: classic `GEN_ANIM_FOUDRE = 39` maps through `file3D` to legacy `anim_index=49`, which loads `anim0050.ldc`; in this viewer that is `ANIM.HQR:49`, not `ANIM.HQR:50`. The visible lightning bolt is also emitted by the animation action `F_THROW_FOUDRE`, not stored in the Twinsen body animation mesh itself.
- LBA2 animation interpolation is not direct `elapsed / duration` truncation. Classic `ObjectSetInterDep` first computes a rounded 16.16 interpolator with `((deltaSteps << 16) + ((nbSteps + 1) >> 1)) / nbSteps`, and `ObjectSetInterFrame` applies that interpolator with signed right shifts. Direct division can be off by one on real ANIM frames.
- Root-level `viewer.py` and `lba_hqr.py` are currently documented compatibility wrappers even though project policy says not to preserve compatibility bridges by default. Treat them as an explicit current-state exception, not a pattern to extend.
- Animation sequence playback needs a separate loop segment. The first frame of that loop segment must interpolate from the last keyframe, not from itself or from the intro frame, or looping idles such as `ANIM.HQR:66` snap at the wrap boundary.
- Playback frames are not uniquely identified by `(frame, elapsed_ms)` once a loop segment exists. Frontend code should carry `sequence_index`/`segment` and loop-cycle count through scrubbing, pause/resume, and repeat playback; otherwise repeat-off can play the synthetic loop segment and translating world-motion animations can snap their root offset on repeat.
- Animation compatibility is not just bone count when File3D metadata exists. `animation_metadata.compatible_body_ids` is an allow-list for `BODY.HQR` models; otherwise same-bone unrelated actors, such as Twinsen wizard tunic and the emperor, can appear to share valid animations.
- `ANIM3DS.HQR` uses classic zero-based HQR indexing like `BODY.HQR`, not the regular one-based archive path used by `ANIM.HQR`. Entry 127 is the `T_ANIM_3DS` frame-range table loaded by the original runtime; treating ANIM3DS as one-based hides frame 0 and shifts the table to the wrong catalog identity.

- Frontend canvas CSS should target explicit viewer canvases. A broad `canvas` selector can accidentally resize tool canvases such as UV or sprite previews to full viewport size and make new inspection panels appear broken.
- In PowerShell debugger scripts, `$PID` is the shell's read-only process id. Do not assign or reuse it as the target process variable for `cdb.exe`; use a different name such as `$targetPid`, or CDB can attach to PowerShell instead of `LBA2.EXE` and produce invalid evidence.

- SCENE life-script opcode layout is easy to undercount around distance predicates. `LF_DISTANCE_3D` consumes a trailing `u8` operand like `LF_DISTANCE`; omitting it misaligns the following comparator and only shows up late on real scene coverage.
- Known RESS resource table entries must be classified before generic LM2 auto-detection. `RESS.HQR:5` is the normal sprite ZV table, but its bytes can pass the permissive LM2 parser as a sparse model if model detection runs first.
- `RESS.HQR:38` has conflicting provenance: classic `COMMON.H` comments slot 38 as empty, while legacy `lba2_ress.hqd` labels it `lim|Shading palettes` and the payload is XPL-shaped. It is not dead data in the retail scene set: `AMBIANCE.CPP::ChoicePalette` selects `RESS_XPL0 + Island`, so island 11 scenes select entry 38 even without a named `COMMON.H` constant.
- `SCREEN.HQR` uses classic zero-based PCR indexing. Parsing it with the regular one-based HQR table skips PCR slot 0 and makes the payload order look reversed. Canonical catalog ids must match `COMMON.H` `PCR_*` constants: even PCR slots are 640x480 indexed images, odd PCR+1 slots are 768-byte palettes.
- `SPRITES.HQR` and `SPRIRAW.HQR` also use classic zero-based indexing. Parsing them as regular one-based archives hides slot 0; for `SPRIRAW.HQR` this creates false missing scene links to `SPRIRAW.HQR:0`. Do not derive a `SPRITES.HQR` catalog entry's backend by calling `resolve_runtime_sprite(SPRITE_3D, entry_index)` because low `SPRITES.HQR` slots are direct UI/system `HQRPtrSprite` entries while projected scene sprites select `SPRITES.HQR` only for Sprite >= 100.
- `OBJFIX.HQR` uses classic zero-based indexing too. `GivePtrObjFix(index)` passes runtime ids directly to `HQR_Get(HQR_ObjFix,index)`, so constants such as `BODY_3D_CLOVER = 60`, `BODY_3D_DART = 61`, and `BODY_SORT_PROTECT = 62` must resolve to `OBJFIX.HQR:60`, `OBJFIX.HQR:61`, and `OBJFIX.HQR:62`, not shifted one-based catalog ids.
- `HOLOMAP.HQR` uses classic zero-based HQR indexing. The regular one-based parser misses `HQR_COORMAPP_HMM = 0`, the 2,244-byte globe UV map loaded by `HOLOGLOB.CPP`; parse this archive with `parse_classic_table` so catalog ids match the `HQR_*` constants.
- `LBA_BKG.HQR` also uses classic zero-based HQR indexing. Entry `0` is the 28-byte `T_BKG_HEADER` loaded by `GRILLE.CPP::InitBufferCube`; using the regular one-based parser hides the header and makes later GRI/BLL/BRK ranges look like unrelated or accidental payloads.
- Retail `LBA_BKG.HQR` BRK `AffGraph` command streams only use run types `0`, `1`, and `2`; no decoded BRK uses a `0xC0`/run-type-3 command. `GRAPH.ASM::AffGraph` would treat bit pattern `11` as a literal copy because it checks bit 6 after testing either high bit, while `CALCMASK.ASM::CalcGraphMsk` checks bit 7 first and would group it with repeat-color runs. Do not invent semantics for run type 3 unless runtime evidence finds a real case.
- GRI decompressed cube cells are two bytes, but a nonzero 16-bit word is not automatically an occupied block. `AffGrille`, `GetColBrick`, and `WorldCodeBrick` read byte 0 as the 1-based BLL block id; if byte 0 is zero, byte 1 may still carry a transparent collision/code value. Treating the little-endian word value as the block id creates false invalid block 0 evidence.
- Two retail scene 125 GRM zones resolve to fragments whose `y0 + dy` is 26, one cell past the nominal 25-cell GRI column height. Do not reject these as impossible: classic `IncrustGrm` does a raw `memcpy` from `GetAdrColonneCube(x,z) + (y0*2)`, so a port/editor model should preserve this as contiguous `BufCube` column-spill evidence unless runtime disassembly proves another guard.
- `TEXT.HQR` uses classic zero-based HQR indexing too. Entry `0` is the English/system `BufOrder` message-id table, and paired entries are `file*2` order tables plus `file*2+1` text banks within each language group. The regular one-based parser hides the first order table and makes dialog IDs look unanchored.
- `SAMPLES.HQR` uses the regular HQR table shape but runtime sample ids are zero-based. `HQF_Init` seeks `index*4`, so `SAMPLE_MAGIC_BALL = 0` loads the first HQR offset slot; catalog sample ids should match runtime ids (`SAMPLES.HQR:0`), not the parser's one-based table entry number.
- Some `SAMPLES.HQR` offset-table slots share the same block offset. If a raw entry length looks absurdly large, check the embedded HQR resource header; the decoded sample uses `compressed_size_file` and may still be valid. Do not infer multi-megabyte audio duration from `HqrEntry.byte_length` alone on duplicate-offset sample slots.
- `ANIM.HQR` must be parsed as animation before generic LM2 auto-detection. Several real animation payloads also pass the permissive LM2 parser; letting LM2 win misclassifies scene animation targets as models.
- For scene objects with `ANIM_3DS`, `animation_number` indexes the `ANIM3DS.HQR:127` range table while the scene `Sprite` field points at the current/start frame inside that range. Do not treat `animation_number` itself as the frame asset id.
- `RESS.HQR:48` ACF movie-name list uses the regular RESS table identity (`parse_table`, catalog entry 48), not classic-zero indexing. Do not load it with `parse_classic_table`; that confuses the ACF list with an empty/nonexistent slot in synthetic and real catalog paths.
- HOLOMAP plan parameter records are easy to misname. Classic `HOLOPLAN.CPP::InitHoloPlan` reads the nine longs as `orgmx, orgmz, offx, offz, alpha, beta, distance, lalpha, lbeta`; do not treat the first fields as width/height or move `distance` earlier in the record.
